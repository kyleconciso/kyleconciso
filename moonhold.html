Project Overview

"Moonhold" is a Godot Engine game developed for the MGC Summer Gamejam 2025. The core premise involves players surviving an alien horde on a celestial body until their ship is ready for ignition. The game features a 3D environment, custom physics and gravity systems tailored for spherical worlds, procedural planet generation, and a robust C# backend for game logic, UI, and system management.

My Role & Contributions

This project was created by a team of three for the MGC Summer Gamejam 2025. As the project's architect, I was specifically responsible for the following:

  • Core Systems Architecture: I designed and implemented the game's core architecture, including all foundational manager systems in C# (scene, audio, input, settings).
  • Game & Entity Logic: I developed the primary game loop and the C# scripts for all major game entities (Player, Alien, Ship, Items), defining their behaviors, state management, and interaction logic.
  • UI Implementation: I was responsible for scripting the UI scenes, including the main menu, HUD, and pause screens, and connecting them to the backend game logic.

Architecture

The codebase follows a modular design, leveraging Godot's node-based architecture and C# scripting. Key components are organized into logical directories, promoting separation of concerns and reusability. The project uses autoloads (singletons) for global systems like AudioManager, SettingsManager, and SceneManager.

High-Level Structure:

  • Core/: Foundational systems for application-wide management (Audio, Settings, Scene transitions, Context).
  • Input/: Dedicated input handling system, abstracting input sources and providing buffering capabilities.
  • Entity/: Game objects (Player, Enemies, Ship, Celestial Bodies, Items, Projectiles) with their unique logic and behaviors.
  • Scenes/: Defines the game's flow and UI screens (Main Menu, Game, HUD, etc.).
  • Assets/: All game resources including 3D models, audio, textures, and custom shaders.
  • Util/: Helper classes and resource definitions, particularly for procedural generation parameters.

Core Systems

Scene Management (Core/Scene)

A global singleton SceneManager.cs manages the game's scenes as a stack. It handles transitions like pushing a pause menu or replacing the main menu. Scenes inherit from a base Scene.cs class, which provides lifecycle methods (DidLoad, OnEnter, OnExit, etc.) and uses a Context.cs object for passing data between scenes.

Audio & Settings Management (Core/)

AudioManager.cs is a global singleton for playing BGM and SFX, using a pool of AudioStreamPlayer nodes for efficiency. It integrates with Godot's AudioServer to control volumes. SettingsManager.cs persists settings like audio volumes and visual toggles to a config file (user://settings.cfg) and emits signals on change.

Input System (Input/)

InputManager.cs orchestrates input events from providers (e.g., KeyboardMouseInput.cs) and dispatches them to receivers that implement the IInputReceiver.cs interface (like the Player). An InputBuffer.cs utility makes actions like jumping more forgiving by buffering them for a short time.

Custom Physics & Gravity (Entity/GravityEntity.cs)

GravityEntity.cs is a base class for RigidBody3D nodes needing to interact with spherical gravity. It automatically detects the nearest CelestialBody as a gravity source, calculates the gravity vector, and smoothly aligns the entity's orientation to the planet's surface. A ShapeCast3D is used for ground detection.

Planetary Generation (Entity/Planet/ & Assets/Shaders/)

The Planet.cs node uses a SphereGenerator.cs to create a base mesh, which is then sculpted by a compute shader defined in PlanetHeight.cs. This resource references PlanetHeight.glsl and exposes configurable noise settings (SimplexNoiseSettings.cs, RidgeNoiseSettings.cs) to the editor. The compute shader applies multiple layers of fractal noise to generate varied terrain, and the final mesh can be used to generate a TrimeshShape for collision.

Key Entity Reference

  • Player.cs: Implements IInputReceiver to handle inputs. Uses a custom PlanetaryMovementController for physics-based movement and manages health, camera, and weapon interactions.
  • Alien.cs: Features basic AI to find and move towards the player or ship, attacking when in range.
  • CelestialBody.cs: Base class for planets. Acts as a gravity source and supports basic orbital mechanics.
  • Gun.cs: Manages ammunition, fire rate, reloading, and temporary stat modifications from power-ups.
  • Item System (Item/): A base Item.cs class handles visual effects and player collision. Derived classes like AmmoItem, HealthItem, and PowerupItem apply specific effects to the player or ship upon collection.

Shaders & Graphics

The project leverages custom GLSL and Godot shaders for its visual style and procedural generation.

  • PlanetHeight.glsl: A compute shader that generates terrain heightmaps using multiple layers of Simplex and Ridge noise.
  • Planet.gdshader: A spatial shader that colors the planet's surface based on altitude and applies roughness/metallic properties.
  • Water.gdshader: Renders a water surface with depth-based coloring and foam effects near the shore by sampling from the DEPTH_TEXTURE.
  • space.gdshader & space_2d.gdshader: Sky and CanvasItem shaders for rendering dynamic, twinkling starry backgrounds in 3D and 2D scenes respectively.
